## Iteration 1

The codename was replaced by the permanent UP identity across resource paths, Lua, events, state bags, SQL, CLI, configuration, Docker, docs, and tests. ADR-0003 makes future naming decisions deterministic. Remaining weaknesses were the lack of an automated naming regression test, CI that did not execute the migration, and an unchecked account-creation transaction.

## Iteration 2

Score: **88/100** — architecture 17, naming 20, security 12, operations 14, tests 13, documentation 9, commercial readiness 3.

An automated naming contract now rejects legacy identifiers and missing canonical paths. CI executes the real MySQL migration, Lua compilation, Go tests, build, and Compose validation. Account creation checks transaction failure and safely resolves a concurrent insert. A clean local validation recreated all nine domain tables plus the migration registry.

## Iteration 3

Score: **90/100** — architecture 17, naming 20, security 14, operations 14, tests 13, documentation 9, commercial readiness 3.

Internal account and character UUIDs were removed from client-facing state responses because the client only needs the public passport and loaded status. This improves data minimization without changing the server-side export contract. The remaining gaps—an actual FXServer integration test, a playable character flow, automated release migrations and premium delivery—belong to the next delivery gates.

Further editorial or naming changes would add at most one point without new runtime capability, below the two-point significance threshold. The review therefore stops at iteration 3.
